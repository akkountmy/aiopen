# Личный слой: свои блоки поверх неизменной основы

Экран «Дашборд» и выпуск «Top news» собраны так, что человек может добавить
**своё**, но не может испортить **основу**. Этот документ — контракт между
сервером, клиентом и проверками. Он же объясняет, почему задача решается данными,
а не ветвлением кода.

## Правило, из которого всё следует

* **Основа** — то, что живёт в коде: шесть блоков дашборда (`src/dashboard.mjs`,
  `DASHBOARD_BLOCKS`), шесть тем выпуска (`src/topnews.mjs`, `CATEGORIES`),
  расписания, промпты основы, отрисовка. Менять это может только владелец кода
  через git и сборку. Ни один пользователь, включая администратора в интерфейсе,
  не создаёт и не удаляет основу.
* **Личный слой** — то, что живёт в состоянии аккаунта (`state.personal[userId]`
  и записи `state.dashboard` с `custom: true`). Человек создаёт здесь свои блоки
  и свои темы, меняет их, удаляет и отменяет — и это не касается ни основы, ни
  других людей.
* **Откат** — журнал обратных действий. Каждое изменение личного слоя и настроек
  задания пишет запись «как было». Одна кнопка возвращает последнее действие,
  не задевая остальное.

Права: личный слой — свой у каждого (`ownerId`), основа — только код. Поэтому
«глубокие изменения» физически не имеют ручки в интерфейсе: их нельзя вызвать,
даже если очень хочется.

## Данные

```js
// index.json
state.personal = {
  [userId]: {
    topics: [{ id, title, kicker, query, extraQueries: [], tone, createdAt }],
    undo:   [{ id, at, kind, label, data }],   // последние 30, старые вытесняются
  },
};

// свои блоки дашборда живут рядом с остальными заданиями
state.dashboard += [{
  id, blockId: 'own_<8 hex>', custom: true, ownerId,
  title, short, description, icon,          // icon — из набора ICONS клиента
  cadence, dayOfMonth, dayOfWeek, hour,
  prompt, enabled, projectId: '', files: [],
  createdAt, updatedAt, nextRunAt, lastRunAt: null, lastStatus: '', lastError: '',
}];
```

Ограничения (`src/personal.mjs`, `PERSONAL_LIMITS`): до 6 своих блоков, до 3
своих тем, название 60 знаков, подпись 120, описание 240, текст задания 2000
(общий потолок основы), тема 40, поисковый запрос 120, журнал 30 записей.

`blockId` своих блоков всегда начинается с `own_`; основа использует короткие
имена (`law`, `taxes`, …). Поэтому конфликт имён невозможен: `ensureDashboardTasks`
досоздаёт только блоки основы, а свои блоки он не трогает и не воскрешает.

## Маршруты

Все — в существующем авторизованном `/api` (переменная `user` уже есть).

### Дашборд

* `GET /api/dashboard` — как раньше плюс
  `personal: { customCount, customLimit, canAddCustom, icons }` (`icons` — набор
  значков для окна создания, чтобы клиент не держал второй список).
  У каждого задания появляется `custom: true|false`, у своих ещё `canReset: false`
  и тексты-заглушки основы вместо `law`/`taxes`.
* `POST /api/dashboard/tasks` `{ title, short?, description?, icon?, prompt, cadence, dayOfMonth?, dayOfWeek?, hour?, enabled? }`
  → `201 { task, ...dashboardPayload }`. Ошибки: `400` (текст по-русски, что именно
  не так), `409` (лимит своих блоков).
* `PATCH /api/dashboard/tasks/:id` — прежние поля; пишет запись журнала.
* `DELETE /api/dashboard/tasks/:id` — базовый блок: мягкое удаление (как сейчас),
  свой блок: настоящее удаление. Оба пишут журнал.

### Журнал и откат

* `GET /api/personal/journal?limit=10` → `{ entries: [{ id, at, kind, label }], canUndo, label, count, topics }`
  (`label` — название последнего действия, его показывает кнопка отката).
* `POST /api/personal/undo` `{ entryId? }` → `{ undone: { label, kind }, …dashboard payload, topics }`;
  без `entryId` отменяется последнее. `409`, если отменять нечего.
* `POST /api/personal/reset` → `{ reset: { removedBlocks, removedTopics, restored }, …dashboard payload, topics }`:
  снять свои блоки и темы, вернуть удалённые блоки основы **выключенными**;
  журнал после сброса пуст — это уже «как было».

Виды записей журнала и что они возвращают (`store.applyUndo`):

| kind | data | откат |
| --- | --- | --- |
| `task-patch` | `{ taskId, before: {…поля…} }` | вернуть поля, пересчитать `nextRunAt` |
| `task-delete` | `{ taskId }` | снять `deletedAt`, оставить выключенным |
| `task-restore-all` | `{ taskIds: [] }` | вернуть `deletedAt` этим заданиям |
| `own-create` | `{ taskId }` | удалить свой блок |
| `own-delete` | `{ task }` | вставить свой блок обратно |
| `topic-create` | `{ topicId }` | убрать тему и её кеш |
| `topic-delete` | `{ topic }` | вставить тему обратно |

### Своя тема в Top news

* `GET /api/topnews` — как раньше плюс
  `personal: { topics: [...], limit, used, blocks: [{ topicId, title, kicker, tone, status, items: [] }] }`,
  где `status` — `ready` | `building` | `empty` | `off`.
* `POST /api/topnews/topics` `{ title, kicker?, query, extraQueries?, tone? }` →
  `201 { topic, personal, undo }`; `DELETE /api/topnews/topics/:id` → `{ personal, undo }`.
  Эти два ответа отдают **своё** состояние выпуска (`personal` здесь — темы и блоки,
  а не счётчики дашборда), поэтому payload дашборда в них не подмешивается.
* Своя тема собирается **фоном** в первый заход после 07:00 по Минску и кладётся
  в `data/topnews/personal/<userId>/<dateKey>.json`. Пока не готова — `building`,
  при неудаче — `empty` с честным текстом. Основа выпуска не пересобирается:
  свои блоки добавляются после шести базовых.

### То же словами в чате

Кнопки — не единственный путь. Если человек пишет «добавь мне блок про склад» или
«заведи свою тему про логистику», агент делает то же самое инструментами:

| Инструмент | Что делает | Пределы |
| --- | --- | --- |
| `add_personal_block` | создаёт свой блок дашборда (`title`, `task`, `short?`, `description?`, `icon?`, `cadence?`, `dayOfMonth?`, `hour?`) | те же 6 блоков, 60/120/240/2000 знаков |
| `add_news_topic` | создаёт свою тему выпуска (`title`, `query`, `kicker?`, `extraQueries?`) | те же 3 темы, 40/60/120 знаков, ≤3 запроса |
| `create_project` | заводит проект и диалог и запускает в нём задание (`name`, `task?`, `projectId?`) | один проект за ход, отказ во вложенном агенте |

Инструменты не прибавляют прав: запись идёт в аккаунт того, кто попросил, лимиты
проверяет тот же код, что и у кнопок. Отказ приходит объектом `{ ok:false, error }`
с русским текстом, и агент обязан пересказать его человеку как есть — например
«Своих блоков уже 6 — больше нельзя. Удалите один на дашборде, и место освободится».

## Ошибки и тексты

Ошибки — `sendError(res, код, 'по-русски, что не так и что сделать')`. Никаких
английских сообщений и никаких кодов вместо фразы. Пример: `«У блока должно быть
название: до 60 знаков»`.

Клиент показывает `error.message` как есть (`toast(error.message)`).

## Что видит человек (обязательно к реализации)

1. **Сетка дашборда — без вводной полосы.** Раньше над сеткой стоял блок «Основа
   остаётся, пробуйте своё» с кнопкой отката; его убрали: правило «добавляйте своё,
   основа не меняется» уже говорят подсказка у кнопки «Свой блок», строка в окне
   создания и плашки «Отменить» после каждого действия.
2. **Значок на карточке**: `Мой блок` (удалить можно, вернётся откатом). У блоков
   основы значка нет — то, что они есть у всех, подписывать незачем.
3. **Кнопка «Свой блок»** в шапке дашборда — открывает окно создания.
4. **Окно создания**: название, что должен сделать агент, расписание; внизу
   строка-предупреждение «Это личный блок: он в вашем аккаунте, основу сервиса
   это не меняет».
5. **Тост с «Отменить»** после создания или удаления — тот же маршрут отката.
   Пока идёт откат, кнопка в тосте говорит «Возвращаем…»: выключенная кнопка со
   старым словом читается как «нажатие не приняли».
6. **Top news**: кнопка «Своя тема» и карточки своих тем после базовых, с тем же
   значком и той же отменой. Пояснительной строки «Основа остаётся…» под
   подзаголовком выпуска тоже больше нет.
7. **Карточка своей темы**: если человек не задал строку под заголовком, вторая
   строка не повторяет название — её роль играет значок «Мой блок».

Тексты пишем как для человека, который боится сломать сервис: коротко, без
технических слов, с ответом «что будет, если я это нажму».

## Границы правки

| Файл | Кто владеет |
| --- | --- |
| `src/personal.mjs`, `test/personal.mjs` | новый модуль личного слоя |
| `store.mjs`, `server.mjs`, `docs/personal-layer.md`, `README.md` | интеграция в ядро |
| `public/app.js`, `public/index.html`, `public/styles.css` | вся отрисовка |
| `src/topnews.mjs`, `src/topnews-personal.mjs` | сборка своих тем |
| `src/tools.mjs`, `src/agent.mjs` | инструмент «создай проект и диалог» |

Каждый файл правит один человек: клиент — монолит на 14 200 строк, и две
параллельные правки в нём гарантированно разойдутся.

## Как проверяем

* `node test/personal.mjs` — 46 проверок: валидация, границы, журнал и откат без
  сети и модели.
* `node test/personal-layer.mjs` — 79 проверок по HTTP на настоящем сервере во
  временной папке данных: основа после каждого действия та же (названия, тексты,
  флаги), лимиты 409, отмена правки/удаления/создания для блоков и тем, готовый кеш
  своей темы приходит блоком, чужой аккаунт не видит и не правит, сброс оставляет
  ровно шесть блоков основы.
* `node test/topnews-personal.mjs` — 58 проверок сборки своих тем с подменёнными
  поиском и редактором.
* `node test/smoke.mjs` — весь API на локальном сервере без вызовов модели.
* `npm test` — оффлайн-набор: ни один прежний файл не сломан.
* Руками в браузере: создать свой блок, отменить, удалить, вернуть; включить
  свою тему и увидеть, что шесть базовых блоков на месте.

| Инструмент «создай проект и диалог» | `src/tools.mjs`, `src/agent.mjs` | 10 сценариев вручную + `test/tools-extra.mjs`, `test/agents.mjs` |
| Инструменты «свой блок» и «своя тема» словами | `src/tools.mjs`, `src/agent.mjs`, обработчики в `server.mjs` | стенд на фейковых обработчиках + `test/tools-extra.mjs` |
| Интерфейс: полоса безопасности, свои блоки, темы, отмена | `public/app.js`, `public/index.html`, `public/styles.css` | вручную в браузере |

Чего сознательно нет:

* администратор из интерфейса не может менять основу — только код и выкладка;
* лимиты поднимаются правкой `PERSONAL_LIMITS` (одно место), а не настройкой на
  аккаунт: иначе «до шести» превратилось бы в «сколько скажет администратор», и
  обещание «основа не растёт от чужих действий» перестало бы быть проверяемым;
* своей темы без поискового запроса не бывает: пустой запрос — это не тема, а
  надежда, и блок из неё собрать нельзя.
