# Паритет: сервис DSH.OPEN.WEB против локального харнесса

Дата: 20.10.2026. Проверял: инструменты, навыки, промпт, ограничения, вычисления.
Коммит сервиса на момент проверки: `4d02b80` (анализ данных, аудит, бизнес-план, ресёрч).

## 1. Что сравнивали

| Слой | Сервис (Amvera) | Локальный харнесс |
|---|---|---|
| Модель | задаётся на сервере, один маршрут | выбирается в настройках, переключение на лету |
| Инструменты | 22 | ~60, включая субагентов и workflow |
| Навыки | 12 каталогов `skills/` | 11 каталогов `~/.dsh/skills` + встроенные навыки харнесса |
| Вычисления | `calculate`, `analyze_data`, формулы в `create_excel` | то же + локальный Python с pandas/openpyxl |
| Веб | `web_search` (1 запрос за вызов), `fetch_url` | `web_search` (1–4 запроса), `web_fetch`, браузер с DOM и скриншотами |
| Память | `remember` (заметки проекта) | постоянная память + поиск по ней + Thread |
| Файлы | только каталог проекта, лимиты размера | весь диск, песочница по политике |

## 2. Инструменты сервиса (полный список, 22)

`analyze_data`, `analyze_image`, `append_file`, `calculate`, `check_document`, `create_excel`,
`create_pdf`, `create_pptx`, `create_word`, `delete_path`, `edit_file`, `fetch_url`,
`find_in_files`, `list_files`, `move_path`, `read_document`, `read_file`, `remember`,
`run_python`, `use_skill`, `web_search`, `write_file`.

Ключевое, чего в сервисе нет и не появится «малой кровью»:

- субагенты и workflow (нет параллельной работы над большими задачами);
- автоматизация браузера (нет нажатий, DOM, скриншотов, входа на сайты);
- MCP-серверы и подключаемые внешние инструменты;
- локальный Python: в облаке `environment: nodejs`, `run_python` вернёт ошибку. Поэтому весь
  «тяжёлый» счёт должен идти через `analyze_data` (потоковое чтение CSV/XLSX, группировки,
  метрики, лимит 2000 строк в ответе) и через живые формулы в `create_excel`.

## 3. Что сделано сегодня для паритета

1. Новый инструмент `analyze_data` (`src/analysis.mjs`, 851 строка): профиль файла, выборки с
   фильтрами, группировки (до 3 полей, с разбивкой по году/кварталу/месяцу/неделе/дню),
   метрики (count, countDistinct, sum, avg, min, max, median, p95, stddev), сортировка, лимит.
   Проверено на 120 000 строк CSV и на XLSX с датами.
2. Исправлен настоящий баг: даты из XLSX в поясе UTC+3 уезжали на день назад, из-за чего
   группировка по месяцам давала лишний месяц. Теперь дата приводится к UTC-полуночи.
3. Четыре новых навыка в двух вариантах — сервисном (только инструменты сервиса) и
   харнессном (pwsh, Python, `check_office.py`): `data-analysis`, `fin-audit`,
   `business-plan`, `web-research`. В харнессе у поля `name` во frontmatter может быть
   только латинский слаг, иначе навык молча выпадает из каталога модели.
4. Восемь экспертных блоков в промпте (было четыре): добавлены «анализ данных», «аудит»,
   «бизнес-планирование», «ресёрч интернета»; `analyze_data` вписан в строку про инструменты.
5. `office-xlsx`, `office-pptx`, `pdf-report`: разделы про большие выгрузки и метрики,
   бюджет слайдов и выбор графика, печатную типографику и структуру отчёта.
6. Тесты: `test/analysis.mjs` (10 тестов, включая 120 000 строк и даты) и проверка новых
   экспертных блоков в `test/docs.mjs`. Все проходят.

## 4. Честные остатки расхождения

- **Python и pandas**: в сервисе недоступны. Всё, что в навыках описано как «через pandas»,
  в сервисе решается `analyze_data` + формулы Excel. Навыки это уже учитывают.
- **Субагенты**: сервис делает длинные задачи последовательно, харнесс распараллеливает.
- **Браузер**: сервис не может пройти по кликам, снять скриншот, залогиниться на сайте;
  ресёрч ограничен `fetch_url`.
- **Поиск**: один запрос за вызов, 6 результатов; несколько формулировок — несколько вызовов
  подряд (в навыке `web-research` это прописано).
- **Дубли навыка аудита** — закрыто: в сервисе остался один `fin-audit` (тело 11,4 тыс. знаков,
  структура под МСА, red flags, существенность и выборка), в харнессе — тот же `fin-audit` в
  варианте с python-кодом и `check_office.py`.

## 5. Вывод

По качеству документов и таблиц сервис уже не уступает: те же движки (docx-pro, exceljs-pro,
pptxgenjs, pdfkit-pro), тот же чек-лист качества, те же навыки. По анализу данных разрыв
закрыт `analyze_data`. Остаются ограничения платформы (нет Python, субагентов и браузера) —
это архитектура сервиса, а не настройки; обходится формулами Excel, потоковым анализом и
последовательными вызовами поиска.

## 6. Ответ в диалоге (добавлено позже, 20.10.2026)

Два навыка про сам ответ, а не про файл, в двух вариантах:

- `answer-structure` — форма ответа под запрос, вывод первой строкой, заголовки-утверждения,
  бюджет длины, каркас разбора «что вижу / чем грозит / что делать», чек-лист перед отправкой.
- `answer-visuals` — таблица 2–5 колонок, матрица 2×2, таймлайн, воронка, иерархия, чек-лист,
  KPI-строка; границы рендера и уход наглядности в файл.

Разница вариантов — в возможностях платформы, и она прописана прямо в навыках:

| Что можно показать | Сервис | Харнесс |
| --- | --- | --- |
| Markdown-таблица, список, цитата, код | да | да |
| Формулы `$…$` | нет (знаки доллара) | да (KaTeX в Web GUI) |
| Редактируемая схема | нет — только таблица в чате | `diagram_create` → вкладка «Холст», правка и экспорт |
| Картинки, Mermaid, HTML-теги в сообщении | нет | нет |
| Настоящий график | `create_excel` + `chart` | `office-xlsx`, затем `present` |
| Готовый файл у пользователя | блок «Файлы проекта» | `present` |

Каталог навыков в подсказке модели подорожал до 3,2 тыс. знаков, поэтому порог теста
`test/parity.mjs` поднят с 3 000 до 3 400 — иначе любой следующий навык требовал бы
сокращать чужие описания.
