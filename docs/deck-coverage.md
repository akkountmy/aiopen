в браузере. Пересечение — либо навык без вёрстки, либо вёрстка без файла.

## 2. Что закрыто у нас

| Слой | Харнесс (`C:\Users\33620\.dsh`) | Сервис (`DSH.OPEN.WEB`) |
| --- | --- | --- |
| Дизайн-система | `deck-design`: токены, 3 палитры, 8 макетов, 1600×900 | те же токены в `assets/deck/deck.css` |
| Рендер | Chrome/Edge → PDF → PNG (PyMuPDF) | `create_deck` → PDF без полей (Chromium) |
| Шрифты | `install_fonts.py`: Montserrat + Oswald в систему | woff2 вложены в файл (`data:font/woff2`) |
| Редактируемый .pptx | `deck-export`: гибрид «скриншот фона + живой текст» | `create_pptx` (родные объекты PowerPoint) |
| Числовая сверка | `compare.py`: средняя разница, горячие пиксели, сдвиг | замер раскладки до печати (DOM-геометрия) |
| QA файла | `qa.py` + просмотр каждого PNG | `check_document`: страницы, размер, текстовый слой |
| Инструкция модели | навык `deck-design`, `deck-export` | навык `skills/deck` |

Итого: по звёздам мы не «повторяем» ни один проект целиком — у нас есть то, чего нет ни у кого
из списка: **числовая сверка рендера и честный выбор формата** (PDF для показа, PPTX для правок).

## 3. Что добавлено 11.11.2026

- `create_deck` в сервисе: спека слайдов → PDF 1600×900 без полей, палитры gold/graphite/cobalt,
  восемь макетов, шрифты внутри файла, откат в HTML, если браузера нет.
- **Замер раскладки до печати** (`deckLayoutProbe` в `src/doc/deck.mjs`, хук `probe` в
  `src/browser.mjs`): в той же странице, что печатает PDF, считаются прямоугольники текста —
  что вылезло за поле слайда, что наложилось, что подгрузилось из шрифтов. Результат приходит
  в ответе строкой «Раскладка: чисто» или «Раскладка: N замечаний — слайд 3 — …». Без
  LibreOffice и второго рендера: числа берутся из DOM, а не из картинки. Аналог нашего
  `compare.py`, только вместо пиксельной сверки — геометрия.
- Вместимость макетов зафиксирована константой `CAPACITY` и проверяется рендером: `rows` 3–4,
  `steps` 3–4, `list` до 5, `kpi` 2–4. Переполнение не проглатывается молча: в ответе
  появляется «Не вошло: Слайд 2 (rows): помещается 4, не вошло 1».
- Навык `skills/deck`: когда `create_deck`, когда `create_pptx`, какой макет под какой вопрос,
  лимиты текста, что делать с отброшенным, чего не обещать.
- Подсказка в системном промпте (`ДИЗАЙН-ДЕКА`) и метка «Дизайн-дека» в строке работы.
- Тесты: `test/deck.mjs` (8 проверок) + `npm run test:deck`; отдельный кейс — «переполнение
  видно до печати»: переполненный макет обязан дать `meta.layout.ok === false`, а не молчание.

## 4. Что сознательно не берём

- **Полный LibreOffice/PPTX-рендер на Amvera.** Контейнер 1 ГБ RAM и без LibreOffice: сверка
  `compare.py` остаётся локальной, в облаке — `check_document` и совпадение числа страниц.
- **HTML-показ в браузере вместо файла** (reveal.js, slidev, open-slide). Наш продукт отдаёт
  файл в «Готовые документы»; показ — это то, что человек уже умеет с PDF.
- **Онлайн-редактор** (PPTist, presenton). Это отдельный продукт, а не инструмент агента.
- **Плагины DSH для презентаций.** `pptwise` (★27) и `ChaosPPT` (★3) — сторонний код без QA-гейта;
  наш навык уже сильнее по проверке. Ставить не стали: риск без выигрыша.

## 5. Как проверить, что работает

```
node test/deck.mjs                                       # 7 проверок инструмента
node -e "import('./src/doc/deck.mjs').then(m=>console.log(m.normalizeDeck({slides:[{layout:'rows',rows:[1,2,3,4,5]}]}).warnings))"
```
Второй командой видно предупреждение о переполнении — это и есть гейт вместимости.
Живая проверка: попросить в чате «сделай деку про …» и открыть PDF из «Готовых документов»:
страниц столько же, сколько слайдов, шрифты не подменены, нижние поля не срезаны.
