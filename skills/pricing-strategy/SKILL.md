# Ценообразование AI-сервиса

Роль — назначить цену за доступ к агенту и доказать её расчётом до объявления прайса.

## Когда включать

- «сколько брать», «посчитай тариф», «какая подписка», «проверь цену»;
- «уходит в минус», «тяжёлые пользователи съедают», «дорогой контекст»;
- «ввести лимиты», «сделать бесплатный тариф», «поднять цену».

## Процесс

1. Собери три опоры: себестоимость, ценность, цены конкурентов. Нет одной — это гадание, недостающее отметь допущением.
2. Себестоимость. В DSH Open Web факт из `src/config.mjs`: `PRICING.inputPerM` / `outputPerM`, `BILLING.multiplier`, `BUDGET.limitUsd`. Формула: `tokens_in/1e6*inputPerM + tokens_out/1e6*outputPerM`.
3. Ценность: за какой результат платят, сколько он стоит клиенту, что стоит альтернатива. Цена = ценность × доля захвата: новый рынок 30–50%, конкурентный 10–25%, коммодити 5–15%, премиум 25–40%.
4. Конкуренты: прямые, косвенные, вариант «не покупает ничего». Таблица «игрок / единица / цена / лимиты» через `web_search`, `fetch_url` и `read_page`.
5. Модель:

| Модель | Когда | Риск |
| --- | --- | --- |
| Подписка на месяц | ровное потребление, нужен прогноз выручки | тяжёлый месяц уводит в убыток, нужен fair-use |
| Предоплаченный баланс USD | неровное потребление, простая механика (так сейчас в DSH Open Web) | оплачено вперёд — нужен порог «мало средств» |
| Оплата по факту | B2B с договором, крупный клиент | кассовый разрыв; новому — предоплата |

6. Единица тарификации: токен (точно, но непонятно), запрос (понятно, но разброс в разы), задача или шаг (по ценности, плохо прогнозируется), месяц (риск безлимита), пакет кредитов. Бери ту, что совпадает со смыслом платежа.
7. Маржа: `(цена − переменная себестоимость)/цена`; ниже 30% — запаса на дорогой запрос нет. Считай по p95 стоимости задачи, а не по средней.
8. Чувствительность: цена −20% / −10% / база / +10% / +20% × объём → выручка и маржа.
9. Тяжёлые: лимит на задачу с подтверждением (`BUDGET.limitUsd`, шаг `stepUsd`), fair-use в подписке, кэш префикса, дешёвая модель на черновиках, обрезка истории.
10. Подъём цены: предупреди за 30 дней с числом и датой; действующим оставь старую цену на N месяцев (grandfathering); добавь ценность в тот же день; сначала новые. Цель — price realization > 85%, churn < 5%.

## Чек-лист перед выдачей

Проверим перед публикацией:

- [ ] себестоимость по факту, вход и выход раздельно;
- [ ] цена ≥ себестоимости p95-задачи, а не средней: длинный контекст и многошаговый прогон не убыточны;
- [ ] у подписки и бесплатного тарифа есть лимит (задачи, токены, fair-use, срок) и стоп на дорогую задачу;
- [ ] при −20% цены маржа положительная;
- [ ] скидка: уровень (0–10% менеджер, 10–20% руководитель, 20–30% директор, 30%+ владелец), объём, срок;
- [ ] пользователь видит единицу, цену, лимит и что при превышении;
- [ ] числа в прайсе, интерфейсе и счёте совпадают.

## Что отдать пользователю

- Вердикт первой строкой: цена X за единицу Y, маржа Z%, средний чек.
- Расчётная таблица:

| Строка | Откуда |
| --- | --- |
| Себестоимость 1M вход / выход | `PRICING` |
| Наценка | `BILLING.multiplier` |
| Средняя и p95 задача в токенах | статистика по дням |
| Себестоимость средней и p95 | формула из п.2 |
| Цена за задачу и за месяц | прайс |
| Маржа на средней / на p95 | п.7 |
| Выручка на 16 пользователей | расход × цена |

- Модели: рекомендация и почему остальные отвергнуты; чувствительность ±20%.
- План объявления: кому, когда, grandfathering, лимиты; форму ответа держи по `answer-structure`.
- Файл — `.xlsx` с формулами (`office-xlsx`), прайс — `.docx`/`.pdf`.

## Анти-паттерны

- Цена «как у конкурента» без знания его себестоимости.
- Цена ниже себестоимости на длинном контексте: запрос прибыльный, проект целиком — убыток.
- Расчёт по средней вместо p95: маржу съедают редкие дорогие задачи.
- Бесплатный тариф без лимитов — подарок самым тяжёлым; скидка без объёма и срока учит клиента ждать.
- Рост выручки при падении маржи — субсидированный объём, а не рост.
- Выносить наружу внутренние цены и множитель наценки.
