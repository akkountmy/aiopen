# MCP-сервер и MCP-скрипт для агента

MCP отдаёт агенту инструменты, которые он зовёт наравне с родными. Оправдан, когда инструментов много или клиентов несколько; для двух операций дешевле скрипт.

## Когда включать
- «сделай MCP-сервер», «выставь API инструментами», «подключи X через MCP»;
- у внешней системы 5+ нужных агенту операций;
- набор нужен нескольким сессиям или облачному сервису (streamable-http);
- существующий сервер надо расширить, не сломав соседние, или агент зовёт не тот инструмент.

## Процесс

1. Решить: сервер или скрипт.

| Признак | MCP-сервер | Node-скрипт |
| --- | --- | --- |
| инструментов | 5+, набор растёт | 1–3 |
| клиентов | несколько, облако | одна машина |
| секреты | env сервера, живут долго | env одного запуска |

Доступ к Amvera (панель, деплой, логи) сделан скриптами, а не сервером: `D:\DSHarness\telegram\deploy\amvera\amvera-login.mjs`, `amvera-mcp.mjs`, `deploy-bridge.mjs` и `D:\DSHarness-0.1\DSH.OPEN.WEB\scripts\amvera-mcp.mjs`, `deploy-amvera.mjs` — инструментов мало, клиент один. JSON там передаётся через `@file.json`: кавычки в аргументах PowerShell съедаются.

2. Спроектировать интерфейс до кода. Имя = verb_noun: `search_tickets_by_status`, не `query`. Описание отвечает «когда вызывать» и что вернёт; не влезает в одно предложение — это два инструмента. У каждого поля тип и дефолт. Данные — JSON.

3. Каркас stdio (TypeScript, официальный SDK):

```ts
import { McpServer } from "@modelcontextprotocol/sdk/server/mcp.js";
import { StdioServerTransport } from "@modelcontextprotocol/sdk/server/stdio.js";
import { z } from "zod";

const server = new McpServer({ name: "tickets-server", version: "1.0.0" });
server.tool(
  "search_tickets",
  "Заявки по статусу. Вызывать, когда нужен список. Возвращает id, заголовок, исполнителя.",
  { status: z.enum(["open", "resolved"]), limit: z.number().int().max(100).default(20) },
  async ({ status, limit }) => {
    try { return { content: [{ type: "text", text: JSON.stringify(await find(status, limit)) }] }; }
    catch (e) { return { content: [{ type: "text", text: `search_tickets: ${e.message}` }], isError: true }; }
  },
);
await server.connect(new StdioServerTransport());
```

Streamable-http — тот же сервер, другой транспорт: stateless, вызовы независимы, порт из env. Ресурсы и промпты дают контекст, но начинать надо с инструментов.

4. Ошибки — данные, не падения. Внешний вызов в try/catch, ответ `isError: true` с текстом для действия («429, повторить позже», «нет AMVERA_TOKEN»). Без stack trace и токенов в контенте.

5. Правила инструмента: одна задача — один инструмент (`get_user` и `update_user`, а не параметр `mode`); идемпотентность (повтор не создаёт второй деплой); таймаут на апстрим и обрезка ответа с флагом `truncated`; стабильные имена полей; валидация на границе, до внешнего API.

6. Подключить и проверить. **На сайте DSH Open Web MCP-серверы не подключаются** — там нет ни MCP-клиента, ни настроек: сервер отдаётся как код и инструкция, запуск — в локальном харнессе. На сайте поэтому не пытайся искать инструменты управления MCP: их нет, шаг «подключить» заменяется шагом «отдать код и инструкцию запуска». В локальном харнессе сервер задаёт патч-слой профиля (инструменты управления подключением: добавить, посмотреть список, перезапустить, выключить), HMR подхватывает сам. Дерево конфигурации: `dsh --dump-config`. Признак поломки: сервер подключён, инструментов 0.

7. Первый вызов руками до передачи агенту: успех, пустой результат, неверный аргумент, недоступный апстрим.

## Чек-лист перед выдачей
- [ ] имена verb_noun и уникальны среди всех подключённых серверов
- [ ] описание говорит «когда», а не только «что»
- [ ] у всех аргументов тип и описание
- [ ] ошибки возвращаются как isError
- [ ] заданы таймаут и лимит ответа, идемпотентность проверена
- [ ] секреты только из env, в выводе маска
- [ ] после перезапуска сервер показывает ожидаемое число инструментов (в локальном харнессе — списком подключённых MCP; на сайте пункт неприменим, здесь MCP не подключается)
- [ ] после правки вызваны и старые инструменты сервера

## Что отдать пользователю
Таблицу инструментов (имя / что делает / аргументы / что возвращает), код сервера или скрипта, конфиг подключения, команду первого вызова с фактическим результатом, список проверенных путей ошибки. Итог строкой: столько-то инструментов, подключено так-то.

## Анти-паттерны
- `query`, `run`, `do`: агент выбирает по имени и промахивается.
- Один инструмент с параметром `mode` вместо двух.
- Stack trace или сырой ответ API в контенте — секреты и мусор в контексте.
- Состояние между вызовами («сначала login») — инструмент обязан работать сам.
- Переименование существующего инструмента: ломает промпты; добавлять новое имя.
- Отдать инструмент агентам, ни разу не вызвав руками.
