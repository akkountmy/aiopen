# Движение: надо ли, чем и за сколько

## Гейт по частоте — решается до кривой
| Как часто | Решение |
| --- | --- |
| 100+ раз в день (шорткаты, палитра команд, тогглы) | **никакой анимации**, никогда |
| Десятки раз в день (hover, навигация по списку) | только почти незаметно, либо ничего |
| Изредка (модалки, drawer'ы, тосты) | стандартная анимация |
| Редко и впервые (онбординг, успех) | здесь живёт бюджет «восторга» |

Действие с клавиатуры — дисквалификатор, а не повод поспорить о кривой. У
Raycast нет анимации открытия — это правильно для того, что открывают сотни
раз в день.

Гейт существует, чтобы иногда выдать ноль строк кода: это успех, а не уклонение.
Ошибочный режим хуже отсутствия анимации: анимировать то, что не должно
анимироваться. Данные, которые читают и с которыми действуют (таблица, график,
дашборд), не двигаются ради стиля.

## Цель: назвать до реализации
Одно слово из списка, иначе не строить:

- **feedback** — подтвердить, что интерфейс услышал;
- **spatial consistency** — показать, откуда пришло и куда ушло;
- **state indication** — сделать смену состояния читаемой;
- **continuity** — сшить контент, который иначе телепортируется;
- **explanation** — показать, как что-то работает (маркетинг, онбординг);
- **delight** — только на редком или первом уровне частоты.

«Выглядит круто» на частом элементе — причина остановиться. Декорация без
цели — анимационный долг: не анимировать статичную область просто потому,
что она есть, и не складывать техники стопкой. На фокусную последовательность
достаточно одной сильной идеи.

## Инструмент — самый дешёвый из работающих
| Задача | Инструмент |
| --- | --- |
| hover, press, цвет, состояние | CSS `transition` |
| вход при монтировании без JS | `@starting-style` |
| предопределённое движение на загруженной странице | CSS `animation` |
| программное управление без библиотеки | WAAPI: `element.animate()` |
| пружины, layout-анимации, exit, жест | Motion/Framer Motion |

Не ставить motion-библиотеку ради fade.

## Кривые и длительности
```css
--ease-out:    cubic-bezier(0.23, 1, 0.32, 1);   /* вход, выход, press — дефолт */
--ease-in-out: cubic-bezier(0.77, 0, 0.175, 1);  /* движение по экрану */
--ease-drawer: cubic-bezier(0.32, 0.72, 0, 1);   /* drawer, sheet */
```
Встроенные CSS-кривые слишком слабы. Нужна другая — брать готовую с
easings.co, а не писать руками; не изобретать `cubic-bezier(0.4, 0, 0.2, 1)`
«потому что знакомо».

Выбор: вход и выход — `ease-out`; движение и морфинг по экрану — `ease-in-out`;
hover и цвет — `ease`; постоянное движение (прогресс, marquee) — `linear`.
**`ease-in` в UI не использовать**: он задерживает ровно тот момент, за которым
наблюдают; `ease-out` на 200 мс ощущается быстрее, чем `ease-in` на 200 мс.

| Взаимодействие | Длительность | Кривая и детали |
| --- | --- | --- |
| Press feedback | 100–160 мс | `ease-out`, `:active { transform: scale(0.97) }` |
| Tooltip | 125–200 мс | `ease-out`, `scale(0.97)` + `opacity: 0` |
| Popover, dropdown, меню | 150–250 мс | `ease-out`, `scale(0.95)`, origin — триггер |
| Модалка | 200–500 мс (обычно 250) | `ease-out`, `scale(0.96)`; backdrop те же 250 мс |
| Drawer, sheet | 200–500 мс | `ease-drawer`, закрыт в `translateY(100%)` |
| Toast | 400 мс | `ease`, не `ease-out` — документированное исключение |
| Аккордеон | 200 мс | `ease-out`, `height` + `opacity` |
| Стаггер-элемент | 300 мс | `ease-out`, задержки 50/90/120 мс |
| Немедленный feedback | 100–150 мс | — |
| Рутинная смена состояния | 150–300 мс | — |
| Layout, overlay, смена вида | 300–500 мс | — |

**Бюджет: UI-анимация под 300 мс.** Модалки, drawer'ы, sheets и тосты — только
они выходят за это с обоснованием. Выход короче входа. Длинный feedback
читается как латентность.

Пружина нужна там, где анимацию могут схватить или развернуть: drag с
моментумом, живой элемент, жест. `{ type: "spring", duration: 0.5, bounce: 0.2 }`
или `{ mass: 1, stiffness: 100, damping: 10 }`; bounce держать в 0.1–0.3 и
не брать рефлекторно — отскок у меню, которое просто проявилось, ощущается
неправильно. Нативное правило Apple: damping 1.0 без отскока, ~0.8 — только
если жест нёс моментум.

## Свойства
Только `transform` и `opacity`. Четвёртое разрешённое — `clip-path`. `height`
терпим **только** у аккордеона, где transform-эквивалента нет.

| Вместо | Анимировать |
| --- | --- |
| `width`/`height`/`padding` | `scale()` |
| `top`/`left`/`margin` | `translate()` |
| `display`/`visibility` | `opacity`, затем `visibility: hidden` |
| `box-shadow` | `filter: drop-shadow` (измерить на своём движке) |

- `transition: all` запрещён — перечислять свойства явно.
- **Никогда `scale(0)`**: вход — `scale(0.9–0.97)` + `opacity: 0`. Чистый fade
  без начального transform — тоже дефект: в реальном мире ничего не появляется
  из ничего.
- `transform-origin` — в триггере для popover, dropdown, меню, tooltip; модалки
  освобождены (они не привязаны к триггеру).
- Проценты в `translate()` считаются от размера самого элемента:
  `translateY(100%)` — надёжнее пикселей.
- Не гнать transform ребёнка из CSS-переменной на родителе: переменные
  наследуются, и пересчитываются стили всех потомков (так lagал drag у Vaul
  после ~20 элементов в drawer'е).
- `will-change` — не «исправление», а последний шаг: ставить на анимируемый
  элемент и только когда сдвиг увидели или измерили; каждый слой стоит
  GPU-памяти. `filter: blur()` — под 20 px, 2–5 px хватает для кроссфейда.

## Прерываемость — главный принцип
Анимацию можно схватить и развернуть в любой момент; ввод не блокируется.
Закрывающуюся модалку, которую поймали снова, ведут за пальцем, а не ждут.

- Всегда анимировать **от текущего значения на экране**, никогда от целевого,
  иначе при прерывании будет скачок.
- Для всего, что ведёт жест, и для того, что триггерится дважды в секунду
  (тосты, тогглы), — `transition` или пружина: они перенацеливаются от
  текущего значения. `@keyframes` перезапускаются с нуля — не для этого.
- При развороте смешивать скорость, а не резать: замена одной анимации другой
  даёт разрыв и «кирпичную стену».
- Жест: 1:1 с пальцем, уважать точку захвата, `setPointerCapture`, порог ~10 px
  до коммита в направлении, `:active`-фидбэк на pointer-down, а не на release.
  Dismiss на флик: мало расстояния — но `velocity > 0.11` закрывает.

## Вход и выход
- Выходить тем же путём, что вошёл: панель справа закрывается вправо, тост
  уходит туда же, откуда пришёл. Вход справа и выход снизу — читается как
  ошибка.
- Backdrop анимируется вместе с модалкой, чтобы читались одной поверхностью.
- После выхода — `visibility: hidden`, иначе слой продолжает ловить клики.
- Смена таба: не интерполировать два цвета, а продублировать список, стилизовать
  копию как активное состояние и анимировать `clip-path` 250 мс.
- Кроссфейд, который не садится: 2 px blur + `opacity: 0.7` на 200 мс — без
  него глаз читает два объекта, меняющихся местами.
- **Стаггер 30–80 мс** для группы, которая появляется как список; один вход на
  контейнер, неравномерные задержки, суммарную задержку ограничивать. Стаггер
  декоративен и никогда не блокирует взаимодействие. Не для списка, мимо
  которого скроллят весь день.

## reduced-motion: меньше и мягче, а не ноль
Убрать движение и смену позиции, оставить то, что помогает понять:
```css
@media (prefers-reduced-motion: reduce) {
  .panel { transition: opacity 200ms ease; transform: none !important; }
}
```
Три сигнала: `prefers-reduced-motion` (кроссфейд без овершута),
`prefers-reduced-transparency` (плотнее фон, убрать blur),
`prefers-contrast: more` (почти непрозрачные фоны и явная рамка).

`:hover`-движение — только внутри `@media (hover: hover) and (pointer: fine)`:
тач даёт ложный hover при тапе. `:active` гейтить не нужно, это настоящий press.
Избегать полноэкранных движущихся фонов, колебаний около 0.2 Гц, резких
скачков яркости и мгновенной смены темы.

## Дёргается — диагностировать по порядку
Бюджет кадра: 16.7 мс на 60 Гц, **8 мс на 120 Гц**; проектировать под меньшее.

1. Какие свойства анимируются? Всё кроме transform/opacity — первый
   подозреваемый: сначала layout-свойства, затем `box-shadow` и `border-radius`
   (они не выглядят layout'ом и легко пропускаются).
2. Совпадает ли дёрганье с занятостью страницы (навигация, fetch, hydration)?
   Тогда перевести на CSS или WAAPI. Кейс Vercel: индикатор таба на shared
   layout во время загрузки следующей страницы ронял кадры; CSS починил.
3. Не ре-рендерит ли React каждый кадр? `setState` в rAF сжигает бюджет —
   писать `ref.current.style.transform`.
4. Не становится ли хуже с ростом контента? Наследуемая CSS-переменная или
   слишком много узлов анимируются одновременно.
5. Есть ли `blur()` больше 20 px?
6. И только теперь `will-change: transform`.

Подтверждать записью, а не ощущением: Performance panel, Animations panel для
замедления, профиль на среднем телефоне. «На моей машине плавно» — не проверка.
В ответе разделять: что проверено по коду и что требует записи на устройстве.

## Приёмка анимации
Флаг ставится сразу, если в коде:

- `transition: all`;
- `scale(0)` и вход без начального transform;
- `ease-in` в UI или слабая встроенная кривая на обдуманной анимации (кроме
  тоста);
- анимация на шорткате, палитре команд, действии 100+ раз в день;
- UI дольше 300 мс без названной причины;
- `transform-origin: center` у привязанного к триггеру popover;
- `@keyframes` на тосте или тоггле;
- анимация `width`/`height`/`margin`/`padding` (кроме аккордеона);
- CSS-переменная на родителе управляет transform ребёнка;
- нет `prefers-reduced-motion` на движении; `:hover`-движение без медиазапроса;
- симметричный тайминг там, где пользователь удерживает и отпускает;
- «всё входит сразу» там, где нужен стаггер.

Формат отчёта: одна таблица `| Было | Стало | Почему |` — по строке на
проблему, затем вердикт по уровням влияния: регрессии ощущения → упущенные
упрощения → производительность → прерываемость и тайминг → origin и физика →
доступность. Ссылки `file:line`, значения точные.

Проверка рендером: снять одно и то же действие дважды — обычный режим и
reduced-motion, — и смотреть снимки before / первый кадр / середина / последний
/ покой. По одному скриншоту о движении не судить.

Готово, когда: движение объясняет feedback, состояние или связь; прерывание и
повторный запуск работают; десктоп, тач и клавиатура не сломаны; reduced-motion
убирает движение, но не смысл; дорогие эффекты плавны на целевом устройстве; и
удаление анимации потеряло бы смысл, а не просто декорацию.

## Если правка исчезнет из памяти
Пользователь поправил тайминг, кривую или запретил вход «из ниоткуда» — это
правило проекта, а не разовая правка: навык `design-rules`.
