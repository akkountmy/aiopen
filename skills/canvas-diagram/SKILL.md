# Схема файлом: SVG, HTML, проверка снимками

На сайте нет инструмента диаграмм и нет холста: схема — это файл SVG, который собирается вручную и проверяется снимком страницы. ASCII-схема в чате не считается результатом — она рассыпается на телефоне.

## Когда включать

- «нарисуй схему», «диаграмма», «архитектура», «флоу», «блок-схема», «дерево», «карта процесса», «покажи связями», «схему файлом».
- В ответе больше 7 узлов, есть ветвление или слои, нужен масштаб, печать либо передача дальше.

## Сначала решить: чат или файл

| Случай | Куда | Чем |
|---|---|---|
| ≤ 7 узлов, один уровень, сравнение | в чат | таблица или список по `answer-visuals` |
| ветвление, слои, много связей, печать, передача | в файл | SVG + HTML, этот навык |
| цифры и динамика | в документ | таблица, затем `create_pdf` |

## Что собирать

1. `diagram.svg` — один самодостаточный файл: `viewBox`, `font-family: system-ui, -apple-system, "Segoe UI", sans-serif`, без внешних шрифтов, картинок и CDN.
2. `diagram.html` — обёртка: заголовок, подпись «как читать», сам SVG инлайном, ширина 100 %. Нужна для `check_page` и для человека, который откроет файл двойным щелчком.
3. Оба файла — через `write_file`. Имена короткие, латиницей: `diagram.svg`, `diagram.html`; пояснение — в чате, а не в имени файла.

## Геометрия, которую видно на снимке

- Сетка 8 px, поля 24 px, узлы выровнены по сетке руками — «на глаз» даёт кривой ряд.
- Чтение одно: процесс — слева направо, иерархия — сверху вниз. Зигзаг и диагонали запрещены.
- Линии ортогональные (`path` с шагом), стрелка — `<marker>`, радиус скругления 6.
- Подпись узла — «глагол + объект», до 3 слов, кегль 13–16 px, одна строка без переносов внутри слова.
- Не больше 9 узлов в ряд: больше — группируй в слои и подписывай слой.
- Подпись связи — что передаётся («заявка», «токен»), не «связь».
- Цвет значит смысл (вход / процесс / хранилище / риск), а не украшает; легенда — если типов линий или цветов два и больше.
- Контраст текста ≥ 4.5:1; светло-серых подписей на светлом нет.

## Каркас SVG

```html
<svg viewBox="0 0 960 540" width="960" height="540" role="img" aria-label="Схема процесса">
  <defs>
    <marker id="arr" viewBox="0 0 10 10" refX="9" refY="5" markerWidth="7" markerHeight="7" orient="auto">
      <path d="M0 0 L10 5 L0 10 z" fill="#334155"/>
    </marker>
  </defs>
  <rect x="24" y="24" width="200" height="64" rx="6" fill="#eef2ff" stroke="#4f46e5"/>
  <text x="124" y="62" text-anchor="middle" font-size="15" fill="#0f172a">Заявка</text>
  <path d="M224 56 H320" stroke="#334155" fill="none" marker-end="url(#arr)"/>
</svg>
```

Координаты считать по сетке: `y` центра узла = верх + половина высоты; подпись по центру — `text-anchor="middle"`, `dominant-baseline="middle"`.

## Проверка — обязательна, до отдачи

1. `check_page` по `diagram.html`, ширины `390,768,1440` — снимки лягут в `screens/`.
2. `analyze_image` по снимку: читаются ли подписи, не налезают ли друг на друга, ничего не обрезано по краям.
3. `read_file` по `diagram.svg`: нет `<image>` с внешним адресом, нет `http://` и `https://` ссылок, `viewBox` совпадает с содержимым.
4. Дефект найден — правь координаты и пересними. Непроверенная схема не отдаётся: «должно выглядеть нормально» не аргумент.

## PDF и документы

`create_pdf` собирает PDF из данных (слайды или A4), вставить в него произвольный SVG нельзя. Страница печати со схемой — по `house-design-drawings` (SVG → PDF через браузер). Документ с рисунком собирай через `office-docx`-подход и после сборки обязательно проверь `read_document`: картинка могла не вставиться.

## Анти-паттерны

- схема символами `+---+` в чате;
- 20 узлов без группировки — читатель не найдёт вход;
- подписи «Блок 1», «и т. д.», «прочее»;
- цвет как декор: двадцать оттенков без легенды;
- отдача файла без снимка и без `analyze_image`.

## Что отдать пользователю

Файлы `diagram.svg` (и `diagram.html`), одна строка «как читать» (направление и что значат цвета или типы линий) и 2–3 вывода, которые схема доказывает. Без пересказа каждого узла.
