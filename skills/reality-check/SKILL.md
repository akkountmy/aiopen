# Проверка реальности перед сдачей

Последний фильтр между «кажется, готово» и «готово»: каждое утверждение подкреплено следом проверки или переформулировано в «не проверял».

## Когда включать

- «готово», «сделал», «всё работает», «можно сдавать» — и вообще перед выдачей отчёта, документа, страницы, кода, ответа в чате.
- Вывод пришёл от субагента или «QA» — чужой отчёт не доказательство.
- Оценка слишком хороша: «0 замечаний», «на 98% готово», «production ready».

## Главное правило

Утверждение без доказательства — не утверждение. Формат: «Сделано: X. Проверено: <команда/файл> → <результат>»; нет следа — пункт уходит в «не проверено». Статус по умолчанию «не проверено»: поднимается он только после проверки. Идеальная оценка без доказательств — красный флаг.

## Расхождения «сказано / на самом деле»

| Сказано | На самом деле | Чем ловится |
|---|---|---|
| «тест прогнан» | скрипт не запускался | прогон заново через `run_js`/`run_python`, вывод и код возврата |
| «на реальных данных» | две выдуманные строки | `read_file`/`find_in_files` источника, число строк |
| «файл готов» | файла нет или он 0 байт | `run_python`: `os.path.getsize(<файл>)`, затем `read_file` |
| «проверил на всех» | проверен один случай | перечень: сколько из скольких |
| «ссылка рабочая» | 404 или редирект на логин | `fetch_url` |
| «все правки внесены» | внесены 2 из 5 | `find_in_files` по каждому пункту |

## Процесс

1. Выписать утверждения из черновика — по одному на строку, рядом ожидаемое доказательство.
2. Собрать доказательства: `read_file`, `find_in_files`, `list_files`, `run_python` (размер, дата), `fetch_url`. Оболочки на сайте нет: команды `pwsh` и `git` не выполняются, проверка строится на инструментах.
3. Сверить объём: сказано пять пунктов — проверять пять.
4. Запустить тест или скрипт заново самому; прошлый прогон и чужой отчёт не считать доказательством.
5. Сопоставить с задачей пользователя построчно; недоделанное — в «не сделано», а не в «сделано».
6. Поставить статус, при сомнении — вниз. Качество оценивать отдельно: первый проход обычно требует 1–3 доработок, автопровал — сломанный сценарий, неработающий интерактив, битый файл. След проверки оставить в отчёте.

## Таблица проверки

| Что проверять | Чем | Провал выглядит как |
|---|---|---|
| Файл есть и не пуст | `run_python`: `os.path.getsize(<файл>)`, дата | 0 байт, «путь не найден» |
| Открывается в программе | `read_document`, `check_document` (структура DOCX/XLSX/PPTX/PDF) | битый архив, пустые страницы |
| Содержимое = заявление | `read_file`, `find_in_files` | заявлено 12 разделов, найдено 7 |
| Код и тесты | `run_js`/`run_python`, повторный прогон, вывод | ошибка в выводе, «тестов нет» |
| Данные реальные | `read_file`/`find_in_files` источника, число строк | сумма не бьётся с источником |
| Ссылка живая | `fetch_url` | 404, заглушка, авторизация |
| Цифры в отчёте | пересчёт из источника | единицы не те, проценты не сходятся |

## Честный статус

- **Сделано** — по каждому пункту назван след проверки.
- **Сделано частично** — что сделано, что нет, почему, что нужно для закрытия.
- **Не сделано** — причина и следующий шаг.

Запрещено: «должно работать», «скорее всего», «в целом готово», «почти всё», «на 98%».

## Чек-лист перед выдачей

- [ ] каждое «сделано» имеет след проверки;
- [ ] размеры и даты файлов сверены, 0-байтных нет;
- [ ] документ открыт целевой программой, а не только прочитан;
- [ ] код запущен заново, exit code 0, вывод соответствует заявлению;
- [ ] ссылки открыты через `fetch_url`, не 404;
- [ ] цифры пересчитаны из источника, единицы указаны;
- [ ] недостающее вынесено в «не сделано», а не сглажено.

## Что отдать пользователю

Блок: **Статус** → **Что проверено и чем** (пункт + команда или файл) → **Расхождения** (заявлено / на самом деле) → **Что осталось и почему** → **Риски**. Для большого объёма — файл-отчёт: «Проверено», «Не проверено и почему», «Расхождения», «Правки», «Решение».

## Анти-паттерны

- рапортовать «готово», не запустив проверку;
- принимать вывод субагента или прошлого прогона за доказательство;
- проверять на выдуманном примере и называть это реальными данными;
- сглаживать недоделку до «в целом готово».
