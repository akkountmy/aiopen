## §1. PRD (одна страница + приложения)

```
# PRD: <название>
Статус: черновик / на ревью / принят   Владелец: <имя>   Дата: <дд.мм.гггг>   Версия: 0.1

## 1. Проблема
[сегмент] в ситуации [когда] не может [результат], потому что [барьер].
Доказательства: <данные, цитаты, частота>. Стоимость проблемы: <деньги/часы/мес> [факт/допущение].

## 2. Цель и метрика
Primary: <метрика> с <A> до <B> за <срок>. Способ расчёта: <событие/знаменатель/окно>.
Secondary: …   Guardrail: <что не должно ухудшиться>.

## 3. Не-цели

## 4. Сценарии
Happy path: <шаги>.

## 5. Требования
R1. Когда <ситуация>, пользователь может <действие>, система <поведение>, результат <состояние>.
R2. …
(каждое требование — проверяемо; без «удобно», «быстро»)

## 6. Нефункциональные
Производительность: <p95>, доступность: <…>, приватность/PII: <…>, лимиты: <…>, локализация: <…>.
```

## §2. Opportunity brief (discovery)

```
Проблема: …   Сегмент: …   Частота: …   Острота (платят ли уже): …
Сейчас решают через: …   Наше отличие: …
Гипотеза: если …, то … (метрика, порог)
Дешёвый тест: <что делаем>, стоимость <…>, срок <…>
Go, если: …   No-go, если: …
```

## §3. RICE-таблица

| Инициатива | Reach (польз./мес) | Impact | Confidence | Effort (чел.-нед.) | RICE | Комментарий |
|---|---|---|---|---|---|---|

Формула: `RICE = Reach × Impact × Confidence / Effort`.
Impact: 3 = массовый, 2 = сильный, 1 = заметный, 0.5 = слабый, 0.25 = минимальный.
Confidence: 100% = есть данные, 80% = есть сигналы, 50% = только логика. Ниже 50% — сначала исследование, не разработка.

## §4. Experiment card

```
Гипотеза: если …, то <метрика> с <A> до <B> за <срок>, потому что <механизм>.
Метод: A/B / switchback / holdout / before-after / прототип — почему: …
Метрика решения: …   Поддерживающие: …   Guardrail: …
Базовая ставка: …   MDE: …   α=0.05, мощность 80% → выборка: …   Срок: …
Риски: подглядывание / novelty / сезонность / пересечение тестов / …
Критерии ДО запуска: успех = …, провал = …, неопределённость = …
Раскатка: 5% → 25% → 100%, стоп-условие: …
```

## §5. Launch-чек-лист

- [ ] продукт: фича включена для сегмента <…>, есть выключатель
- [ ] биллинг: тариф/лимиты/возвраты проверены
- [ ] поддержка: FAQ, скрипты ответов, известные ограничения
- [ ] аналитика: события проверены на проде, дашборд создан
- [ ] юридическое: оферта/согласия/обработка PII
- [ ] коммуникация: кому и когда (продажи, поддержка, маркетинг)
- [ ] откат: как выключаем за 10 минут, кто решает
- [ ] порог «притормозить»: <метрика> хуже <значения> за 48 часов

## §6. Диагноз падения метрики

```
Метрика: определение (числитель/знаменатель/окно/когорта) — менялось ли?
Декомпозиция: метрика = <трафик × конверсия × частота × чек>; изменилось звено: …
Разрез: время (когда началось) / сегмент / платформа / канал / версия
Технические причины проверены: трекинг, релиз, сбои — да/нет
Гипотезы: H1 … H2 … H3 …   Чем отличаем: …   Срок проверки: …
Решение: чинить сейчас / исследовать / переопределить метрику
```
