# Эксплуатация и рантбуки

Надёжность измеряется минутами недоступности. Один человек не дежурит ночами: отказ должен видеть сторож, лечение — идти по плану.

## Когда включать
- «бот молчит», «контейнер перезапускается», `Insufficient RAM`;
- «выкатываем», «как откатить», «что проверить после деплоя»;
- «какие метрики смотреть», «настрой алерт», «какой SLO», «напиши рантбук».

## Процесс

1. **Назови поверхности и отказ каждой.**

| Поверхность | Проверка |
|---|---|
| Сайт DSH.OPEN.WEB — Amvera, порт 3123, `/data` | `GET /api/health` → `ok`, `/api/version` сменился |
| Мост «Василины», роль `bridge` | `node work/watch-bridge.mjs 60` → `up=`, `online=` |
| Воркер ноутбука, роль `worker`, `watchdog.ps1` | свежесть `bot-health.json`: пишется после ответа моста |

Процесс жив, а связь мертва — это авария: 26.10.2026 бот три часа не доходил до моста.

2. **SLO в человеческих числах.** 99% за 30 дней — около 7 часов простоя, 99,9% — 43 минуты; каждый следующий «девять» дороже вдесятеро. Бюджет ошибок — разрешение: цел — добавляй, сгорел — сначала надёжность. Формулируй так: «43% бюджета, прошло 60% срока».

3. **5–7 метрик, каждая отвечает «что делать».**

| Метрика | Где | Порог |
|---|---|---|
| `/api/health` | `scripts/watchdog.mjs`, раз в час | два прогона подряд не 200 |
| 5xx и p95 | журнал `[server]`, `scripts/measure-live.mjs` | больше 5–10% за 10 минут |
| Память | журнал Amvera, `/api/status` | петля `Insufficient RAM`, рестарты |
| Мост и воркер | `watch-bridge.mjs` (`queued=`), `bot-health.json` | очередь стоит; связь старше 10 минут |
| `/data`, копия | `fs.statfs`, `data/backups` | меньше 10% свободно; копия старше суток |

4. **Алерты двух уровней.** «Будить»: сайт не отдал 200 два прогона, бот молчит больше 10 минут, рестарт-петля, мост 503. «Утром»: место, копия, p95, очередь. Алерт без действия удаляй.

5. **Деплой: одна команда вперёд, одна назад.** До выкатки зафиксируй коммит и версию сборки в кабинете Amvera — это и есть откат. Мост: `cd D:\DSHarness\telegram\deploy\amvera`, затем `node make-bundle.mjs`, `node deploy-bridge.mjs files`, `build`, `node fetch-logs.mjs 1`. Сайт: `node scripts/deploy-amvera.mjs`, проверка `check-p1-live.mjs`. Переменные — через `deploy-bridge.mjs env`, только секретами. Порядок: ноутбук, потом облако. Миграции без простоя: новое поле читается и старой версией; данные в `/data`, файлы атомарно; `maxResumes` не поднимает то, что валит контейнер.

6. **До выкатки.** [ ] зелено `node test/smoke.mjs` и `test:runs`; [ ] конфиг в переменных, локальный fallback не затирает боевой; [ ] секрет из хранилища: `$env:DSHOW_PASS = & "$env:USERPROFILE\.dsh\secrets\_vault.ps1" get dshow-monitor -Field password`; [ ] известна версия для отката.

7. **После выкатки.** [ ] `Invoke-RestMethod https://dshopen-vladimir00177.msk1.amvera.tech/api/health` → `ok`; [ ] `/api/version` сменился; [ ] вход и одна живая операция проходят; [ ] нет `Insufficient RAM` и новых `[server]`; [ ] мост как до выкатки; [ ] через 15–30 минут перечитать журнал.

8. **Рантбук — страница на каждый отказ:** симптом, проверка, действие, если не помогло.
```
Симптом: бот молчит, в bot.log «мост ответил 503».
Проверка: node work/watch-bridge.mjs 60    -> up=, online=, queued=
           node work/ops-cloud-check.mjs; node deploy/amvera/fetch-logs.mjs 1
Действие: node work/ops-cloud-cancel.mjs jobs, затем all (снесёт и полезные)
Не помогло: воркер перезапустится сам (watchdog.ps1, 10 минут).
```
Разбор — в `telegram/INCIDENT-<дата>.md`: причина цепочкой, правки, MTTR.

## Чек-лист перед выдачей
- [ ] поверхности и отказ каждой названы;
- [ ] SLO в минутах, метрик 5–7, у каждой источник и порог;
- [ ] алерты «будить» и «утром», у каждого действие;
- [ ] есть версия для отката и команда проверки;
- [ ] секреты не напечатаны, в рантбуке есть «если не помогло».

## Что отдать пользователю
Таблица поверхностей, SLO в минутах, метрики, чек-листы «до» и «после» в README проекта (`D:\DSHarness\telegram\README.md`) или `docs/`, рантбук в `telegram/runbooks/<симптом>.md`. Команды — копируемые как есть, с путями проекта; оболочки на сайте нет, поэтому рядом с командой — что именно она должна показать.

## Анти-паттерны
- SLO 99,99% у сервиса на одного человека: сгорит на первом рестарте.
- Секрет в командной строке или журнале — считай, утёк.
- Починка руками в обход деплоя: следующая выкатка вернёт сломанное.
- Разбор «кто виноват»: системная причина не найдена, авария повторится.
