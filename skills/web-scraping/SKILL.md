# Скрапинг страниц

В проекте нет отдельного платного парсера: `scrape_page` — это Mozilla Readability (движок «Режима чтения» Firefox) плюс Turndown для Markdown и CSS-селекторы. Всё работает локально и бесплатно, без ключей. Для сайтов на JavaScript — Chromium через Playwright, если он есть в окружении.

## Инструменты

| Инструмент | Когда |
|---|---|
| `scrape_page` | Главный: чистый Markdown статьи, текст, поля по селекторам, при необходимости — отрисовка JS |
| `read_page` | Заголовок, описание, оглавление, таблицы, ссылки, текст; удобно перед `crawl` |
| `fetch_url` | Страница, PDF или открытый API; POST, свои заголовки |
| `fetch_many` | До 6 адресов параллельно, ошибки не срывают остальные |
| `crawl` | Обход домена по внутренним ссылкам, до 20 страниц, глубина до 2 |
| `web_search` | Найти адреса, когда их ещё нет |

## scrape_page

Параметры:

- `url` — полный `http(s)://…`.
- `format` — `markdown` (по умолчанию), `text` или `json`.
- `selectors` — объект «поле → CSS-селектор». В селекторе можно указать `@attr`: `"link":"a.buy@href"`, `"cover":"img@src"`, `"date":"time@datetime"`.
- `render` — отрисовать страницу браузером; `wait_selector` — дождаться элемента; `wait_ms` — пауза.
- `max_chars` — предел результата (по умолчанию 30000).
- `timeout_ms` — предел загрузки при render.

Примеры:

```text
scrape_page(url="https://habr.com/ru/articles/…", format="markdown")
scrape_page(url="https://shop.example/item", selectors={"name":"h1","price":".price","old":".old-price","buy":"a.buy@href"})
scrape_page(url="https://spa.example/catalog", render=true, wait_selector=".card", format="json")
```

Если передан `selectors`, результат — JSON с полями; несколько совпадений одного селектора становятся массивом, одно — строкой. Без `selectors` и с `format:"json"` возвращается структура статьи: заголовок, описание, оглавление, таблицы, ссылки, текст.

## Выбор стратегии

1. **Одна статья, документация, новость** → `scrape_page(format="markdown")`. Markdown сохраняет заголовки, списки, ссылки и таблицы — модели проще цитировать.
2. **Конкретные поля** (цена, название, автор, дата, артикул) → `selectors`. Не вырезай поля регулярками из текста: селектор точнее и переживает смену вёрстки лучше.
3. **Таблица** → `format:"markdown"` (таблица придёт как pipe-table) или `format:"json"` + селекторы строк. `read_page` дополнительно отдаёт таблицы массивами.
4. **Каталог/раздел** → `read_page` → внутренние ссылки → `crawl`; либо собрать URL по шаблону пагинации и `fetch_many`.
5. **Контент только после JS** → `render:true` + `wait_selector`. Без render такая страница честно вернёт пустой/сервисный текст — это сигнал, а не повод выдумывать данные.
6. **API вместо HTML** → `fetch_url` с `method:"POST"`, `body` и `headers`. Это надёжнее scraping и не нарушает правил.

## CSS-селекторы

- `h1`, `.price`, `#main`, `[data-testid="price"]`.
- `article h2` — заголовки внутри статьи; `main p` — абзацы.
- `a[href*="/product/"]` — ссылки по фрагменту.
- `table tr:nth-child(2) td:first-child` — ячейка таблицы.
- `:nth-of-type`, `:not(...)`, `,` (объединение) поддерживаются.
- `@href`, `@src`, `@datetime`, `@content` — атрибут; без `@` берётся текст.
- Селектор с ошибкой возвращает `{"error":"Некорректный селектор: …"}`, а не молча пустоту.

Сначала проверь селектор на одной странице и выведи 2–3 значения. Потом запускай на всех.

## Качество и ограничения

- **Проверяй, что это статья, а не меню.** Плохой признак: «войти», «корзина», cookie, много коротких строк без заголовка. Тогда `render` или другой инструмент.
- **Сверь ключевую цифру глазами** на странице: неверный селектор даёт чужое значение без ошибки.
- **Ограничивай объём**: `max_chars`, `crawl` — `max_pages`, `fetch_many` — до 6. Для модели 8–20 тыс. символов обычно достаточно.
- **Не обходи авторизацию, капчу и платный доступ.** Уважай robots.txt, личные данные и авторские права. Для API используй официальный endpoint.
- **Не выдумывай данные**, если страница не отдалась. Верни ошибку инструмента и предложи другой источник.
- **В облаке Chromium может отсутствовать**: `render:true` вернёт понятную ошибку. Сначала пробуй без render.
- **Локальные адреса закрыты** (SSRF): `localhost`, `127.`, `10.`, `192.168.`, `169.254.` недоступны, кроме локальной разработки с флагом.

## Если не работает

| Симптом | Действие |
|---|---|
| Пусто или только меню | `render:true`, `wait_selector`; проверь основной контейнер через `read_page` |
| 403/429 | Пауза, меньше параллельных запросов, другой источник; не долби сайт |
| Поля пустые | Селектор не тот или контент в JS → `render:true`; проверь `@attr` |
| Таблица не в Markdown | Она свёрстана из `div` → собери поля селекторами |
| Ответ обрезан | Увеличь `max_chars` или сузь задачу до нужного раздела |
| Ошибка браузера | Повтори без `render`; в облаке браузера может не быть |

## Связка с ресёрчем

`web_search` → выбрать 2–4 первоисточника → `scrape_page`/`read_page` по каждому → сверить цифру минимум с двумя независимыми источниками → в ответе дать значение, единицу, период и ссылку. Сниппет поиска — не факт: читай страницу.
