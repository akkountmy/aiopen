# Разбор материалов

Три операции встречаются почти в каждой второй рабочей задаче и при этом не требуют ни одной новой зависимости: распаковка zip, проверка ссылок и построчное сравнение версий. Раньше их приходилось имитировать вручную — читать архив вслепую, доверять ссылкам на слово, сравнивать два договора глазами. Теперь для каждой есть инструмент.

## Когда какой инструмент

| Задача | Инструмент | Что на выходе |
|---|---|---|
| Принесли `Материалы.zip` | `extract_archive` | Список распакованных файлов и что пропущено |
| Ссылки в отчёте, письме, ответе | `check_links` | Код ответа, редирект, удалённая страница |
| «Сравни версию 1 и версию 2» | `compare_documents` | Строки «− было» и «+ стало» |
| Что внутри архива, но читать не нужно | `list_files` | Дерево папок после распаковки |
| Нужен текст файла из архива | `read_document` | Текст с разметкой по формату |
| Нужны цифры из выгрузки | `analyze_data` | Профиль колонок, затем `query` |

## extract_archive

- `path` — архив внутри проекта, `to` — куда распаковать (по умолчанию папка с именем архива без расширения).
- Поддерживается **zip** и одиночный **gz**. `.rar`, `.7z`, `.tar` не поддерживаются: скажи это прямо и предложи пересобрать в zip — не выдумывай обходной путь.
- Вложенные папки сохраняются, служебный мусор (`__MACOSX`, `.DS_Store`, `node_modules`) отбрасывается, записи с выходом из папки проекта — тоже: это защита, а не ошибка.
- Существующие файлы не перезаписываются без `overwrite=true` — так повторный разбор не затирает правки.
- Порядок работы: `extract_archive` → `list_files` → по типам: документы `read_document`, таблицы `analyze_data`, страницы `scrape_page`/`read_page`.

Если в ответе есть строка «Пропущено», упомяни её одной фразой: человек должен знать, что часть файлов не развернулась и почему.

## check_links

- `urls` — до 12 адресов, либо `path` — файл, из которого ссылки вытаскиваются сами (`.md`, `.html`, `.txt`, документы Word/PDF).
- Тело страницы не скачивается: проверка не тратит трафик и не ждёт тяжёлых сайтов.
- Что видно в ответе: код ответа, «страница удалена» (404/410), «сервер закрыл автоматическую проверку» (401/403/429 — это не признак смерти), редирект на другой сайт, подозрительный тип файла.
- Правило: ссылка, которая не открылась, **не остаётся в отчёте**. Замени её на живую или убери, а если заменить нечем — напиши, что источник недоступен, вместо того чтобы оставить битый адрес.
- Для ссылок на будущее (не свои) проверяй только те, что попали в текст ответа или файла. Перебирать весь поисковый результат не нужно.

## compare_documents

- `left` — старая версия, `right` — новая. Формат любой: docx, xlsx, pptx, pdf, txt, md, html, csv.
- Сравнение построчное, по значимым строкам: пустые строки и лишние пробелы не считаются различием, перестановка слов — считается.
- В ответе: сколько строк в каждой версии, «отличий N: удалено A, добавлено B», затем сами строки с `−` и `+`. На очень больших файлах выравнивание заменяется сравнением по составу строк — итог об этом честно предупреждает.
- Дальше объясняй сам: инструмент показывает **что** изменилось, а «стало хуже/лучше» и «это существенно» — твой вывод. Для договора пройди по изменениям, которые меняют деньги, сроки и ответственность, а не по каждой запятой.
- Если просят «проверь, что подрядчик поменял», порядок такой: `compare_documents` → по найденным изменениям `read_document` нужных разделов → вывод по рискам.

## Типичные ошибки

1. **Просить пользователя распаковать архив самому.** Архив в проекте — распаковывай инструментом.
2. **Считать 403 мёртвой ссылкой.** Сайт может просто не пускать робота — так и напиши.
3. **Отдавать в ответе ссылку, которую не проверил**, если рядом стоят цифры из неё. Цифра и источник должны быть живыми вместе.
4. **Сравнивать версии глазами на документах в сотни строк.** Машина найдёт отличия точнее и дешевле, твоя работа — объяснить их.
5. **Распаковывать архив в корень проекта.** Иначе десятки файлов смешаются с текущими; пусть будет своя папка.
